PHASE 4B — MENTOR INTELLIGENCE

Context

Current verified state:

* backend-phase4a-stable
* Mentor Foundation complete
* Flyway V1–V10 applied
* Assessment Evaluation Engine complete
* AssessmentCompletedEvent exists
* Skill updates via event listeners
* Progression updates via event listeners

Current flow:

Assessment → Evaluation → Metrics → Skill Updates → Progression Updates

Goal

Implement deterministic Mentor Intelligence that generates insights and recommendations from existing data.

Strict constraints:

* No AI / LLM / external APIs
* No new modules
* No architecture changes
* No modification of existing evaluation, skill, or progression logic
* Must remain event-driven and consistent with current system

System must:

* Be idempotent
* Prevent duplicates
* Handle errors autonomously
* Fix integration issues if encountered
* Remain consistent with existing schema and patterns

---

EVENT INTEGRATION

Subscribe to:

AssessmentCompletedEvent

Create:

MentorEventListener

Requirements:

* Use @TransactionalEventListener(AFTER_COMMIT)
* No direct dependency from assessment module
* Fully event-driven
* Handle missing data gracefully
* Retry-safe and idempotent

---

MENTOR INSIGHT GENERATION

Create:

MentorInsightGenerator

Input sources:

* assessment_metrics
* user_skills
* user_progression

Insight types:

TECHNICAL
APTITUDE
BEHAVIORAL
COMMUNICATION
READINESS

Rules:

* Technical < 60 → improvement insight
* Aptitude < 60 → improvement insight
* Behavioral < 60 → improvement insight
* Communication < 60 → improvement insight
* Readiness > 80 → strong readiness insight
* Readiness < 50 → readiness improvement insight

Requirements:

* Avoid duplicate insights for same user + type + assessment
* Handle missing metrics safely
* Persist to mentor_insights

---

MENTOR RECOMMENDATION GENERATION

Create:

MentorRecommendationGenerator

Rules:

* Low technical → roadmap fundamentals
* Low communication → communication practice
* Low aptitude → aptitude exercises
* Low readiness → skill strengthening

Requirements:

* Deterministic mapping only
* Prevent duplicate active recommendations
* Reuse existing recommendations if applicable
* Persist to mentor_recommendations

---

SERVICE LAYER

Create:

MentorIntelligenceService

Responsibilities:

* Orchestrate full flow
* Validate input data
* Call generators
* Persist results
* Ensure transactional integrity

Requirements:

* @Transactional
* Idempotent execution
* Safe reprocessing
* Graceful failure handling
